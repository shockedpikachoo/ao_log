# ao_log · 알비온 온라인 아시아 서버 킬 기록 수집

알비온 온라인 장비 도감의 장착 순위와 '1:1 참고 순위'에 쓸 새 표본을 모으는 저장소입니다.

## 하는 일

- GitHub Actions가 공식 킬 기록 API(아시아 서버)를 4분마다 확인해 새 기록을 받습니다.
- 받은 기록은 20분마다 `data/` 폴더에 저장되고 자동으로 커밋됩니다.
- 한 번 실행되면 약 5시간 45분 동안 수집하고 끝납니다. 각 실행이 시작할 때 다음 실행을 미리 대기열에 넣고(매시간 17분 예약도 함께 사용), 앞 실행이 끝나는 즉시 이어서 수집합니다.
- 멈추기 전까지 계속 수집합니다. 설정에 적힌 끝나는 시각은 **2027년 12월 31일 23:59(한국 시간)** 입니다(`collector/config.json`의 `stopAt`).

## 도감 업데이트 방식

1. 수집은 쉬지 않고 계속됩니다.
2. 도감을 업데이트할 때는 직전 업데이트 이후에 쌓인 기록을 표본으로 씁니다. 순위 등락(▲▼)은 직전 판과 비교한 것입니다.
3. 표본으로 쓴 기록은 `data/`와 `logs/`에서 지우고, 그 뒤의 기록은 다음 업데이트를 위해 계속 쌓습니다.

| 도감 판 | 표본 기간(한국 시간) | 표본 |
| --- | --- | --- |
| 2026.10.23 | 10월 17일 00:00 – 10월 23일 00:00 (6일) | 단독 처치 81,452건 |
| 2026.10.30 | 10월 23일 00:00 – 10월 30일 00:00 (7일) | 단독 처치 89,407건 |
| 다음 판 | 10월 30일 00:00 – 다음 업데이트 때 | 쌓이는 중 |

지금 `data/`에는 2026년 10월 30일 00:00(한국 시간) 이후 기록만 있습니다. 지운 파일도 커밋 기록(History)에는 남아 있어서 필요하면 되살릴 수 있습니다.

작업 순서(업데이트하는 사람용):

```sh
git pull
# 1) 직전 업데이트 끝 시각부터 이번 끝 시각까지 집계 (한국 시간, 끝 시각은 포함하지 않음)
python3 tools/aggregate.py . <최신 도감 HTML> 2026-10-30T00:00 <이번 끝 시각> agg.json
# 2) agg.json으로 도감 HTML을 다시 만들고 검증
# 3) 쓴 기록 지우기 (--dry-run으로 먼저 확인)
python3 tools/prune.py <이번 끝 시각> --dry-run
python3 tools/prune.py <이번 끝 시각>
git add -A data logs && git commit -m "data: prune events used for the guide" && git push
```

집계 규칙은 `tools/aggregate.py` 맨 위에 적혀 있습니다. `tools/prune.py`는 실행 중인 수집기가 쓰고 있는 로그 파일은 건드리지 않습니다.

## 저장하는 내용

플레이어 이름, 길드, 플레이어 ID는 저장하지 않습니다.

| 대상 | 항목 |
| --- | --- |
| 모든 기록 | 이벤트 번호(`i`), 시각(`t`, UTC), 가해자 수(`n`), 그룹 인원(`g`) |
| 단독 처치 (`n`·`g`가 모두 1) | 위 항목, 기록 종류(`ty`), 처치 구역(`a`), 가해자 명단이 처치자 한 명인지(`pk`), 그룹 명단이 비었거나 처치자 한 명인지(`gk`), 평균 IP(`ki` 처치자 · `vi` 사망자), 장비 10칸의 아이템 코드(`ke` 처치자 · `ve` 사망자) |

장비 칸 순서: 주무기, 보조 장비, 머리, 몸통, 신발, 가방, 망토, 탈것, 물약, 음식. 빈 칸은 `null`입니다.

수집 상태(읽은 페이지 수, 새 기록 수, 시간 범위, 빈 구간 여부)는 `logs/`에 남습니다. `"gap": true`가 있으면 그 사이 기록 일부를 받지 못했다는 뜻입니다.

## 잘 돌고 있는지 확인하기

- 커밋 목록에 `data: +N events (M solo) ...`가 20분마다 쌓이면 정상입니다.
- **Actions** 탭의 *Collect Asia kill events*에 실행 중 1개와 대기 중 1개가 보이면 정상입니다. 대기하다가 새 예약으로 바뀐 실행은 'cancelled'로 표시되며, 이것도 정상입니다.
- 바로 시작하려면 Actions → *Collect Asia kill events* → **Run workflow**를 누르세요.

## 멈추기 · 다시 켜기

- 멈추기: Actions → *Collect Asia kill events* → 오른쪽 위 `…` → **Disable workflow**
- 다시 켜기: 같은 곳에서 **Enable workflow**를 누른 뒤 **Run workflow**
- 끝나는 시각 바꾸기: `collector/config.json`의 `stopAt`
- 용량: 기록은 하루에 약 9MB씩 쌓입니다. 업데이트 때마다 쓴 기록을 지우므로 `data/` 폴더는 업데이트 사이 기간만큼만 커집니다. 커밋 기록을 포함한 저장소 전체는 압축되어 하루 1–2MB씩 늘어납니다.
